# 正式实验协议（运行前冻结）

冻结日期：2026-11-21。机器：M4 / 16 GB Mac，Conda `ppo`。参数快照见 `configs/ppo/base.yaml`，配置矩阵见 `configs/ppo/ablation.yaml`，机器可读协议见 `configs/protocol.json`。

## 预算依据

默认配置仅使用验证集进行了 102,400 步短跑，耗时约 29.0 秒。平均原始回报从 −840.040 改善到 −1.496，CVR 从 72.66% 降至约 0.06%，末次能耗约 14.881 kWh/七天。控制链路有效；这不证明已收敛，也不用于宣称参数优劣。短跑曲线和运行元数据保存在 `results/pilot/`。

正式预算固定为每次 **512,000 环境交互步**（250 个 rollout）。它是短跑预算的五倍，用于比较样本效率和后期稳定性。所有配置使用相同预算，不根据最终测试结果给某个配置额外训练。

## 控制变量

- 策略/价值网络各两层 64 单元，Tanh，高斯动作，CPU。
- 单环境，每批 2048 步，mini-batch 64；学习率固定 3e−4，gamma 0.99。
- 观测归一化，原始奖励；评估冻结统计、确定性动作。
- 熵系数 0、价值系数 0.5、梯度范数上限 0.5、优势归一化开启；不启用价值裁剪或 KL 提前停止。
- 三个待研究参数按单因素矩阵改变；训练种子 `[0,1,2]`，共 21 次独立训练。
- 每次完整更新后判断是否到达 20,480 步验证间隔；最终使用固定预算末次模型。
- 两个独立进程并行，每进程一个 PyTorch 计算线程，使用 `screen` 保持运行。

## 条件与评价

验证集每类天气 5 条固定物理条件，最终测试每类 10 条；两组条件无重复，文件 SHA-256 已记录在协议中。训练仍使用环境默认的随机场景、天气偏移和初态分布。测试不参与调参或模型选择。

规则控制器包括关闭空调，以及舒适中点 ±0.5°C 死区的满功率继电控制。所有控制器使用相同最终测试条件。

主指标为 CVR、degree-hours、kWh、原始回报，按每类天气及三类等权总体汇总。首先计算每个训练种子的场景均值，再跨三个训练种子报告均值与样本标准差。额外报告耗时与 PPO 更新诊断。

代表性轨迹固定为各天气的 `test_<scenario>_00`，展示默认配置的训练种子 0 与规则控制器；不按最终表现挑选轨迹。

## 记录与限制

每个运行保存代码哈希、Git 版本、依赖、完整环境和训练参数、条件快照及产物校验值。报告逐项展示原始结果，包括波动、不显著差异和可能退化，不预设最优参数或节能结论。

三种训练种子只提供有限的随机性估计；实验只覆盖所选参数范围与简化合成房间，不推断所有参数交互或真实建筑部署效果。并行进程的耗时还会受到 Mac 温度和系统负载影响。
